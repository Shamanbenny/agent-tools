# Standard Note Template

Use this as the canonical shape for all new maintained notes. Existing legacy notes may remain as references, but they are not the format to copy.

## Metadata Table

| Field | Value |
|---|---|
| Title | Short human-readable title |
| Created | `YYYY-MM-DD HH:MM` |
| Last Updated | `YYYY-MM-DD HH:MM` |
| User | OS username or confirmed display name |
| Repo / Codebase | Repository or system name |
| Workflow | e.g. `grilling`, `debug`, `faq` |
| Status | `Active`, `Blocked`, `Resolved`, `Reference` |
| Summary | One sentence on why this note exists |
| Tags | Comma-separated topic tags |

## References Table

| Type | Name | Location | Relationship |
|---|---|---|---|
| Repository, issue, document, or URL | Visible label | Path or link | Why it matters |

## Recommended Sections

### Context

Summarize the current problem or question in a few lines.

### Findings

Capture confirmed facts, not raw thought dumps.

### Decisions

Record decisions with rationale when that rationale will matter later.

### Open Questions

List unresolved items that still block progress or confidence.

### Next Steps

Keep this actionable and short.

### References

Store useful repository paths, URLs, or related note links.

### Update Log

Only include this when there were multiple meaningful updates over time.
